# 健身打卡 FitCheck

个人用的健身打卡工具。部署在 GitHub Pages 上，iPhone 用 Safari 打开后「添加到主屏幕」，
从主屏幕图标打开就和普通 App 一样：全屏、无地址栏、能离线用。

不需要 Xcode，不需要开发者账号，不需要服务器。数据存在手机本地浏览器里。

---

## 一、部署到 GitHub Pages（一次性，约 2 分钟）

### 1. 建仓库
打开 https://github.com/new
- **Repository name** 填 `fitcheck`
- 选 **Public**（私有仓库用 GitHub Pages 需要付费）
- **不要**勾选 Add a README / .gitignore / license，要一个完全空的仓库
- 点 Create repository

### 2. 推代码
仓库建好后，在终端里执行（把代码推上去）：

```bash
cd <本项目目录>
git push -u origin main
```

### 3. 打开 Pages
仓库页面 → **Settings** → 左侧 **Pages**
- Source 选 **Deploy from a branch**
- Branch 选 **main**，目录选 **/ (root)**
- 点 Save

等 1 分钟左右，访问地址就是：

```
https://5huji.github.io/fitcheck/
```

## 二、装到 iPhone 上

必须用 **Safari**（Chrome 在 iOS 上不行）：

1. Safari 打开 `https://5huji.github.io/fitcheck/`
2. 点底部中间的「分享」按钮（方框加向上箭头）
3. 往下找到 **「添加到主屏幕」**
4. 确认名字是「健身打卡」，点「添加」

之后从主屏幕图标打开，就是全屏 App 的样子了。

> **顺序很重要**：一定要先添加到主屏幕，再从主屏幕图标打开。直接从 Safari 标签页用会有功能限制。

## 三、四个页面怎么用

### ① 今日
打开就看到「今日未完成 / 今日已完成」。
- **完成打卡**：选身体状态（很累 / 还可以 / 轻松），可写备注，保存
- **开始训练**：跳到计时页
- 已经打过卡：可以「修改今日打卡」或「撤销」
- 显示连续打卡天数、累计训练次数、最近训练时间

### ② 计时
- 选时长：10 / 20 / 30 / 45 / 60 分钟，或用「−/+」按 5 分钟调整（1–300 分钟）
- **开始** → 圆环转动，倒计时开始
- **暂停** → 计时停住（暂停时不会响铃）
- **继续** → 接着剩余时间走
- **结束** → 清零回到初始
- 倒计时走完 → 播放铃声 + 震动（安卓机型），并弹出「去打卡」

### ③ 记录
- 顶部：总训练次数 / 连续打卡天数 / 本月次数
- 下面按月份分组列出所有记录
- **点一条** → 修改身体状态和备注
- **长按一条** → 删除

### ④ 设置
- 默认训练时长（进计时页自动选中）
- 训练结束提醒开关
- 导出备份（JSON 文件）
- 清空全部记录
- 查看当前运行模式（标签页 / 已添加到主屏幕）

## 四、⚠️ 关于"到点提醒"，你必须知道的三件事

**这是网页版和原生 App 唯一的实质差距，先说清楚。**

苹果的规定是：iPhone 上的网页通知必须走「推送订阅 + 服务器发送」这条链路，
**纯本地的网页通知在 iOS 上不被支持**。你没要服务器，所以：

| 场景 | 能不能到点响铃 |
|---|---|
| 训练中页面保持在前台（屏幕亮着） | ✅ **能，准时响** |
| 屏幕自动变暗但没锁 | ✅ 能 |
| 锁屏 / 切到别的 App | ❌ 不行，会**推迟到你回到本页时**立刻响 |
| 安卓手机、电脑浏览器 | ✅ 后台也能响（有系统通知） |

为此做了三件事：

1. **训练期间自动让屏幕保持常亮**（Wake Lock），屏幕不会自动黑掉，这是最主要的手段
2. **回到页面立刻校正时间**：不管你在后台待了多久，一回来就按真实时间重算；
   如果已经过了结束时刻，立刻补响铃 + 弹提示，**不会静默丢失**
3. 计时状态存在本地，App 被系统回收后重开也能接着走

**所以：训练时把手机放旁边、让这个页面开着就行。** 想真正解决锁屏提醒，只有两条路：
换回原生 App（需要装 Xcode），或者加一个推送服务器（你说不要）。这两条路随时可以走。

## 五、数据存在哪、会不会丢

数据保存在手机浏览器的 **localStorage** 里，格式是一串 JSON。特点：

- 关闭 App、重启手机都不丢
- **不上传任何服务器**，只有你这台手机有
- 会丢的情况：清除 Safari 网站数据（**会**）、手机恢复出厂（**会**）

保险做法：设置页点「**导出备份**」，会下载一个 JSON 文件。

## 六、想改代码

所有代码就 4 个文件，没有构建步骤，改完直接刷新浏览器就能看到：

| 文件 | 干什么的 |
|---|---|
| `index.html` | 页面结构（4 个页面的骨架） |
| `app.css` | 样式（配色、卡片、深色模式） |
| `app.js` | 全部逻辑，开头有详细的章节索引 |
| `sw.js` | 离线缓存 |

`app.js` 的结构：

```
1. 常量与工具函数
2. 数据层        —— 读写本地存储
3. 统计计算      —— 连续打卡天数等
4. 音频          —— 到点响铃（代码合成，不需要音频文件）
5. 屏幕常亮      —— Wake Lock
6. 通知          —— 尽力而为
7. 计时器        —— 核心：记住"结束时刻"而不是每秒减一
8. 界面渲染      —— 今日 / 计时 / 记录 / 设置
9. 打卡弹窗
10. 启动
```

**第二阶段要加的东西，位置都留好了**：

- **训练类型**（力量/跑步/游泳/瑜伽/拉伸）：`app.js` 里加一个类型表，
  打卡弹窗多一行选择器，记录对象多一个 `type` 字段即可，老数据不受影响
- **每周目标（比如每周 4 次）**：在 `computeStats()` 里加一个本周计数，
  首页统计条加一格
- **数据分析趋势图**：`computeStats()` 已经算好每月次数，用 SVG 手绘折线即可

改完推上去：

```bash
git add -A && git commit -m "说明改了什么" && git push
```

Pages 会自动更新，手机刷新一下就生效（Service Worker 用的是「网络优先」策略，
联网时永远拿最新代码，断网才用缓存）。
